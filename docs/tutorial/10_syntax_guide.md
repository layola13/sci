# SA 语言语法与关键字解析指南

对于第一次接触 SA (Safe Assembly) 语言的开发者来说，其扁平、显式且专为所有权检查和 LLVM-C 代码生成设计的语法可能会让人感到陌生。

本章将梳理 SA 语言中独特的**语法符号**、**指令助记符**以及**结构布局约定**，帮助初学者快速消除疑惑。

---

## 1. 独有的语法符号

| 符号 | 名称 | 核心用途与物理含义 |
| :--- | :--- | :--- |
| `!` | **销毁符 (Destructor / Drop)** | 标志着一个寄存器的生命周期在此处被**消费或终止**。 |
| `^` | **借用还回符 (Return Borrow)** | 用于函数参数或返回中，显式声明“将借用所有权还回”或“接收一个还回的借用”。 |
| `@` | **函数引前符 (Function Prefix)** | 指向一个声明好的导出函数或外部 `extern` 符号的物理入口。 |
| `&` | **借用操作符 (Borrow)** | 产生对当前寄存器内存的只读或可变借用引用。 |
| `+` | **偏移寻址符 (Offset)** | 相当于传统高级语言的 `.`。由于 SA 无结构体，所有字段通过指针偏移量定位。 |

### 销毁符 `!`
线性所有权规定：每一个分配的寄存器在函数结束前，要么被当作参数传走，要么被 `return` 返回，否则必须使用 `!` 显式销毁。
```sa
x = add 0, 10
!x // 显式告知 Referee 检查器：寄存器 x 的生命周期在此处终结，可以安全回收
```
如果你漏写了 `!x`，Verifier 就会报错：`Variable x is unused or leaked`。

### 借用还回符 `^`
在函数签名中，如果函数参数是借用指针，且你想在执行完毕后把这个指针所有权归还给调用者，使用 `^` 修饰：
```sa
// 接收并借用一个指针，操作完后还回
@modify(^p: ptr) -> ^ptr:
L_ENTRY:
    store p+0, 99 as u64
    return p
```

### 偏移寻址符 `+` 与结构体模拟
SA 没有传统的 `struct.field` 成员访问语法。SA 的数据结构只是一段扁平的内存块。
定义结构体的方法是使用 `#def` 常量来定义每个字段相对于基地址的**字节偏移量**，然后使用 `+` 进行地址运算：
```sa
#def User_SIZE = 16
#def User_age  = +0   // 偏移 0 字节
#def User_id   = +8   // 偏移 8 字节

@process(u: ptr):
L_ENTRY:
    // 读取 u+User_id 处的 u64 整数。相当于 u.id
    id = load u+User_id as u64
    
    // 写入 u+User_age 处。相当于 u.age = 25
    store u+User_age, 25 as i32
    
    !id
    return
```

## 2. 独有的指令助记符

SA 的指令是极其底层的，大部分直接映射到 LLVM IR。

### 比较助记符
SA 区分了**有符号比较**与**无符号比较**：

| 助记符 | 物理含义 | 示例与等价逻辑 |
| :--- | :--- | :--- |
| `eq` | 等于 (Equal) | `res = eq a, b` |
| `ne` | 不等于 (Not Equal) | `res = ne a, b` |
| `slt` | **有符号**小于 (Signed Less Than) | 针对负数比较：`slt -5, 2` $\to$ `1` |
| `ult` | **无符号**小于 (Unsigned Less Than) | 针对内存大小/正数：`ult index, len` |
| `sgt` | **有符号**大于 (Signed Greater Than) | `sgt temp, 0` |
| `ugt` | **无符号**大于 (Unsigned Greater Than) | `ugt size, limit` |
| `sle` / `ule` | 有符号 / 无符号 小于等于 | |
| `sge` / `uge` | 有符号 / 无符号 大于等于 | `uge val, 1024` |

## 3. 控制流与入口标签

### `L_ENTRY` 标签
在 SA 汇编中，所有函数体的第一行都必须是 `L_ENTRY:`。这是函数的**默认入口点标签**。
```sa
@my_func() -> void:
L_ENTRY:
    // 函数体代码从此开始
    return
```

### 标签 (Labels) 与跳转 (`jmp`, `br`)
没有 `if/else` 大括号，只能通过控制流跳转实现：
```sa
    cond = eq x, 0
    br cond -> L_IF_ZERO, L_IF_NOT_ZERO

L_IF_ZERO:
    !cond
    // 执行零值逻辑...
    jmp L_END

L_IF_NOT_ZERO:
    !cond
    // 执行非零逻辑...
    jmp L_END

L_END:
    return
```
注意：如果我们在 `L_IF_ZERO` 块中销毁了某个寄存器，编译器会强迫我们在 `L_IF_NOT_ZERO` 中也同样处理它，或者在跳转合并点 `L_END` 处进行逻辑处理。

## 4. 类型强修饰 (as 类型)

进行 `load` 或 `store` 时，SA 必须显式声明数据的类型，以便底层进行内存对齐和类型安全分析：
```sa
    // 显式声明将地址 p+0 处的数据读取为 i32 类型
    val = load p+0 as i32
    
    // 显式声明将 99 写入地址 p+8 处，数据类型为 u64
    store p+8, 99 as u64
```
常用的类型标识包括：
- `u8`、`u16`、`u32`、`u64`：无符号整型。
- `i8`、`i16`、`i32`、`i64`：有符号整型。
- `f32`、`f64`：浮点数。
- `ptr`：内存指针。

## 5. 宏指令 (EXPAND)

由于 SA 强调零运行时开销，标准库中许多常用方法（如 `VEC_PUSH`）均在编译阶段通过 Flattener 内联展开。
调用宏时，必须在前面冠以关键字 `EXPAND`：
```sa
    // 展开并内联 VEC_NEW 宏的代码，生成并初始化变量 v
    EXPAND VEC_NEW v
```
宏调用中的参数以 `%` 声明作为占位符，但在具体的代码书写中，我们会直接传入真实的寄存器名（无需加 `%`）。
