  SA 项目全面评估报告

  一、项目概况

  SA (Safe Assembly / 安全汇编) 是一门低级安全汇编语言工具链，具备：
  - 线性所有权语义 + Referee 验证器
  - LLVM-C 直接 Bitcode 生成 
  - WASM 输出目标
  - 完整标准库 (sa_std)
  - 模块化插件生态 (sa_plugins)

  规模指标：

  │   维度   │   主项目   │  插件系统   │
  ├──────────┼────────────┼─────────────┤
  │ 源文件   │ 2,059 模块 │ ~1,475 文件 │
  ├──────────┼────────────┼─────────────┤

  二、性能评估

  2.1 当前状态

  编译流水线耗时（pre-push 实测）：
  unit-framework      284s  ← 最大瓶颈
  wasm-matrix         180s
  plugin-host-smoke   143s
  sa-std-runtime       82s
  std-smoke            57s

  已有的并行化（做得好的地方）：
  - 函数级并行验证（verifier.zig 分块原子计数器）
  - 函数级并行代码生成（emit_llvm_llvmc.zig Worker 线程）
  - 测试级并行执行（test_runner.zig 原子队列）

  2.2 性能问题清单

  └─────────────────────────────────────┴──────────────────────────────────┴──────────────────────┘

  P2 — 低优先级：
  - 无 flamegraph/perf 集成，缺乏热点可视化
  - 无运行时内存 profiling（heaptrack/valgrind）
  - 无每次 CI 编译时间趋势跟踪

  2.3 性能改进计划

  优先级 1：缓存 Import 展开结果
    目标：unit-framework 从 284s → ~120s
    方案：在 flattener 中构建 import 解析缓存，
          key = (文件路径 + mtime)，跨编译单元共享

  优先级 2：拆分 feature_suite.sa
    目标：单次从 54.7s → ~15s（4 路并行）
    方案：按语言特性分组成 4-6 个独立 .sa 文件

  优先级 3：Arena 池化
    目标：减少 page_allocator 系统调用 ~30%
    方案：主线程维护 ArenaPool，子任务借用归还

  优先级 4：修复 fs 测试并发问题
    目标：解锁 std_fs_macro_surface.sa 并行
    方案：每个测试使用独立临时目录（std.testing.tmpDir）

  优先级 5：插件并行构建
    目标：build-all.sh 壁钟时间减半
    方案：GNU parallel 或 Zig build 并发步骤

  - 错误消息包含内部路径（开发者工具可接受）
  - JSON 清单解析无 fuzzing 覆盖
  - URI 解析边界情况未 fuzz 测试

  3.3 安全改进计划

  S1：插件 .so 文件完整性校验
    将 sap.json 中的 artifacts.sha256 字段与加载前实际
    文件哈希比对，防止被篡改的动态库加载

  S2：开发模式显式警告
    SA_PLUGIN_DEV=1 时打印明确警告到 stderr，
    避免生产环境误用

  S3：建立 Fuzzing 套件
    对 JSON manifest 解析、URI 解析、SAI 文件解析
    添加 libfuzzer 目标（Zig 内置支持）

  S4：威胁模型文档化
    在 docs/ 中新增 threat_model.md，记录：
    FFI 边界假设、插件沙箱边界、已知 TOCTOU 窗口

  S5：权限最小化审计
    扫描所有 sap.json，标记超出实际需要的权限模式

  四、全面综合评估

  4.1 架构质量

  优点：
  - 编译器流水线清晰分层（Lexer → Verifier → Flattener → LLVM Emitter）
  - 插件 ABI 设计简洁（薄层 dlopen/dlsym，描述符版本检查）
  - 所有权模型原创且完整（Cell/RefCell/Rc/Arc 全实现）
  - 标准库覆盖全面（93 模块，媲美成熟语言）
  - Zig 作为实现语言选择合适（无 GC，内存可控，编译期计算）

  待改进：
  - cli.zig 5,624 LOC 过于庞大，应拆分为子命令模块
  - sa_std.zig 8,083 LOC 单文件运行时，可按域拆分
  - 插件系统 plugins.zig 3,418 LOC，权限/加载/通信逻辑混杂
